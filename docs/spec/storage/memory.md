# メモリ ストレージプロファイル（草案）

[共通契約](../core-contract.md)を、単一プロセスのメモリ上で実現するための草案である。集約ヘッドをスナップショットから分け、seq_nr で追記を照合する。

> 2026-10-05 作成。1 章の判断はすべて未合意である。本文の MEM 規則も草案であり、判断に依存する箇所には「未合意」と書く。[実装計画](../../plan/implementation-plan.md)の IP-D4 は、メモリでも適合を宣言する方針の合意であり、この文書の案を採用したという意味ではない。現行実装を変更する指示ではない。用語は [CONTEXT.md](../../../CONTEXT.md) に従う。

## 1. この文書で決める判断

草案での案を各判断の最初に置く。各案の利点と欠点は、この章の比較表に示す。共通契約の規則自体は変更しない。

| 判断 | 草案での案 | 主な代案 | 状態 |
|:--|:--|:--|:--|
| MEM-D1 | 単一プロセスで使い、保存先の寿命が終わると全記録を失う。永続化しない | 同じ前提で、利用中の明示的な全消去も提供する | 未合意 |
| MEM-D2 | 新規生成は独立した保存先とする。同じ保存先を明示的に共有するインスタンスだけが記録を共有する | 1 つのインスタンスだけで使い、別インスタンスへの共有を提供しない | 未合意 |
| MEM-D3 | ストア全体の排他制御の中で照合と全書き込みを行い、まとめて確定する | 集約単位の排他制御で、同じ集約の照合と全書き込みをまとめて確定する | 未合意 |
| MEM-D4 | イベントの読み取りは、排他制御の中で同じ時点の全件を取得する | 開始時のヘッド h と不変の記録を確保し、排他制御を解いてから h まで読み切る | 未合意 |
| MEM-D5 | 最新スナップショット封筒とヘッドの seq_nr の組を原子的に読む | 封筒とヘッドを別々に読む。組のずれを R-8 に従って扱う | 未合意 |
| MEM-D6 | 確定後、書き込みと同じ排他制御の中で履歴を取り除く | 確定後に排他制御を解き、別の保持操作で取り直す | 未合意 |
| MEM-D7 | 保持の失敗はログで知らせ、次の追記後の保持処理で再試行する | 通知用のコールバックで知らせ、次の保持処理で再試行する | 未合意 |
| MEM-D8 | 最初の版では期限切れ方式を提供しない | 期限の印と猶予を持ち、各操作時に期限切れの履歴を取り除く方式を提供する | 未合意 |
| MEM-D9 | 最初の版では変更フィードを提供しない | 任意の変更フィードを提供し、ヘッド遷移を追記と同じ確定に含める | 未合意 |
| MEM-D10 | フィードを提供するなら、保存先の寿命中は遷移を無期限に保持し、集約内の順序を保って渡す | 有限の保持期間と、順序が入れ替わりうる転送経路を提供する | 未合意 |
| MEM-D11 | 保存先が不変の設定を持ち、共有するインスタンスはその設定を使う | インスタンスごとに設定を受け取り、共有する保存先の設定と生成時に照合する | 未合意 |
| MEM-D12 | 同じ保存先への並行呼び出しを実装が保護する。複数スレッドからの利用も対象にする | 呼び出し側が全操作を直列化することを前提にする | 未合意 |

MEM-D1・MEM-D2・MEM-D12 は SP-1 の前提を定める。MEM-D3 は H-1、MEM-D4 は R-5、MEM-D5 は R-8 に対応する。MEM-D6〜MEM-D8 は S-3・S-4、MEM-D9・MEM-D10 は共通契約の 6 章・F-2・F-5 に対応する。MEM-D11 は共通契約の設定エラーと、共有する書き手の設定をそろえる方法を定める。MEM-D10 は MEM-D9 で提供を選ぶ場合の判断である。

| 判断 | 案 | 利点 | 欠点 |
|:--|:--|:--|:--|
| MEM-D1 | 寿命の終了で全記録を失う | 読み書き中の全消去を扱わずに済む | 試験などで空に戻すには、新しい保存先が必要である |
| MEM-D1 | 明示的な全消去も提供する | 同じ保存先を空に戻せる | 全操作を停止し、旧インスタンスと購読位置を無効にする手順が必要である |
| MEM-D2 | 保存先を明示的に共有する | 複数の利用者が同じ集約への追記を照合できる | 共有と独立生成を区別する操作が必要である |
| MEM-D2 | インスタンス間で共有しない | 記録の所有者が明確になる | 利用者は同じインスタンスを渡して使う必要がある |

| MEM-D3 | 集約単位で排他制御する | 異なる集約を並行して扱える | 設定と全件の再同期には、別に一貫した境界が必要である |
| MEM-D4 | 同じ時点の全件を取得する | 読み取り途中の追記を含めるか迷わず、全件性を確認しやすい | 件数が多いと排他制御の時間が長くなる |
| MEM-D4 | h までの不変の記録を確保する | 排他制御の外で結果を組み立てられる | h 以下の記録が欠けず、取得中に変化しないことを保証する必要がある |
| MEM-D5 | 組を原子的に読む | 封筒の seq_nr がヘッドを上回らない | 2 つの値を同じ読み取り境界に置く必要がある |
| MEM-D5 | 別々に読む | 個別の記録を独立に読める | 封筒がヘッドより新しくなる場合を利用者が扱う必要がある |
| MEM-D6 | 確定後も同じ排他制御で保持する | 次の操作の前に通常の保持件数へ戻せる | 履歴が多いと書き込みの待ち時間が延びる |
| MEM-D6 | 別の保持操作で排他制御を取り直す | 追記の排他制御を早く解ける | その間に増えた履歴も含め、最新の件数を読み直す必要がある |
| MEM-D7 | ログで知らせる | 追記の返り値と通知を分けやすい | 利用者が保持の失敗を集計するにはログの監視が必要である |
| MEM-D7 | コールバックで知らせる | 利用者が通知を直接扱える | 通知の失敗や再入を追記から切り離す必要がある |
| MEM-D8 | 期限切れ方式を提供しない | 時計と期限の管理が不要になる | 遅延削除の挙動をこの保存先では試せない |
| MEM-D8 | 操作時に期限を確認して取り除く | 猶予を設けた保持を扱える | 時計の管理が増え、操作がなければ物理的な削除が進まない |
| MEM-D9 | フィードを提供しない | 転送経路と購読位置を管理せずに済む | この保存先では変更フィードを使う利用者の試験ができない |
| MEM-D9 | 任意のフィードを提供する | 共通契約に沿った購読も試せる | 確定時の遷移保存と再同期の実装が増える |
| MEM-D10 | 寿命中の無期限保持と順序維持 | 停止期間による遷移の欠落を避けられる | 遷移の保持量が増え続ける |
| MEM-D10 | 有限保持と順序の入れ替わりを許す | 保持量を抑え、転送経路を独立に構成できる | 重複・欠番処理に加え、期限超過の検出と全件の再同期が必要である |
| MEM-D11 | 保存先の不変の設定を共有する | 書き手間の設定の食い違いを作らずに済む | 設定を変えるには新しい保存先が必要である |
| MEM-D11 | 各インスタンスの設定を照合する | 利用者が要求する設定との不一致を検出できる | 全インスタンスで同じ照合項目と規則を保つ必要がある |
| MEM-D12 | 実装が並行呼び出しを保護する | 利用者が別に排他制御を用意せずに済む | 同期と競合時の動作を実装・検証する必要がある |
| MEM-D12 | 呼び出し側が直列化する | 実装の同期処理を減らせる | 全共有インスタンスの読み取りと保持も、利用者が同じ制御下に置く必要がある |

## 2. 保存先の寿命・共有・設定を照合する

- **草案・必須 MEM-1**: 単一プロセスのメモリだけを使う。ファイルへの保存、再起動後の回復、プロセス間の共有は範囲外とする。保存先の寿命が終われば、ジャーナル・ヘッド・スナップショット・設定と、提供する場合のフィードの記録を失う。検出できる範囲外の構成は設定エラーにする（SP-1）。この前提と全消去を提供しない案は未合意である（MEM-D1）。
- **草案・必須 MEM-2**: 新しい保存先の生成は空の独立したストアとする。同じ保存先を明示的に共有するインスタンスは、全記録・設定・排他制御を共有する。名前が同じという理由だけで保存先を共有しない。この共有範囲は未合意である（MEM-D2）。
- **草案・必須 MEM-3**: 生成時に保持件数などの設定を検査する。保持件数 0 と、未提供の期限切れ方式・変更フィードを要求する設定は設定エラーにする。設定を保存先に置き、共有インスタンスに別の設定を持たせない。利用中は変更しない。この設定の置き場所と変更方法は未合意である（MEM-D8・MEM-D9・MEM-D11）。不正な設定値を設定エラーにする分類は共通契約の 4 章・S-1 に従う。
- **草案・必須 MEM-4**: 実装が同じ保存先への読み取り・書き込み・保持の並行呼び出しを保護する。複数スレッドから同時に呼んでも、確定前の途中状態は読めない。このスレッド安全性の要求は未合意である（MEM-D12）。特定の言語の同期手段は指定しない。

MEM-D11 の代案では、保持件数・保持方式・フィードの有無と、提供する能力の猶予・保持期間を生成時に照合する。保存先の設定が欠ける場合や不一致の場合は設定エラーにし、自動で上書きしない。

## 3. aid の完全一致と seq_nr で記録を分ける

| 記録 | 識別に使う値 | 内容 |
|:--|:--|:--|
| ジャーナル | aid 文字列、seq_nr | イベント封筒 |
| 集約ヘッド | aid 文字列 | 最新の seq_nr と、その位置のイベント封筒 |
| 最新スナップショット | aid 文字列 | スナップショット封筒。ない場合もある |
| スナップショット履歴 | aid 文字列、seq_nr | 保持件数を設定したときの封筒 |
| 設定 | 保存先 | 保持件数、提供する能力の設定 |

- **草案・必須 MEM-5**: aid 文字列を T-1 に従って組み立て、完全一致で比較する。aid と seq_nr は別の値として扱う。ハッシュ値だけを識別に使わず、前方一致で別の集約の記録を選ばない（SP-2）。型名・バイト長・整数・時刻の範囲は共通契約どおりに検査する。
- **草案・必須 MEM-6**: メタデータとペイロードを分けて持つ。利用者の書き込み後の変更や、取得結果への変更が保存済みの値を変えないようにする。ペイロードの型には T-6 を超える独自の要件を課さない。直列化したペイロードを保持し、取得時に復元する方法などを使える。具体的な保存形式は言語の実装に任せる。

## 4. 照合と書き込みを同じ排他制御の中で確定する

- **草案・必須 MEM-7**: 入力検査と、失敗しうるペイロードの準備を済ませる。その後、次の処理をストア全体の排他制御の中で行う。確定の方法と排他制御の範囲は未合意である（MEM-D3）。

```text
排他制御を始める
  ヘッドを aid の完全一致で読む
  新規作成ならヘッドの不在を確認し、更新なら W-8 を照合する
  イベント封筒、ヘッド、任意のスナップショットと履歴の変更を準備する
  フィードを提供するならヘッド遷移も準備する
  準備した変更をまとめて公開する（ここで確定）
  必要な保持処理を行う（失敗しても確定を取り消さない）
排他制御を解く
保持の失敗があれば別経路で知らせる
書き込みの成功を返す
```

「まとめて公開する」は、別の操作から途中状態が見えないという意味である。準備中の失敗では、公開する記録を変えない。部分的な変更を残したまま失敗を返す方法は使わない。集約ヘッド・ジャーナル・スナップショットと、提供する場合のフィードが同じ確定に従う（H-1）。

照合はヘッドの seq_nr だけに対して行う（H-2）。イベントだけの seq_nr = 1 の追記も新規作成できる（W-3）。ヘッドのない更新は位置 0 とみなし、W-8 の飛び番として拒む。snapshot.seq_nr と event.seq_nr の不一致は W-9 の契約違反にする。エラー分類とメッセージは共通契約の 4 章に従う。

## 5. 読み取りごとに同じ時点の値を返す

- **草案・必須 MEM-8**: 最新スナップショット封筒とヘッドの seq_nr は、同じ排他制御の中で原子的に読む。ヘッドがなければ「なし」を返す。ヘッドがあれば、封筒がなくても組を返す（R-1〜R-3・R-8）。原子的に読む案は未合意である（MEM-D5）。
- **草案・必須 MEM-9**: イベントの読み取りは、同じ排他制御の中で条件に合う全件を取得する。開始時点は、排他制御を取得して記録の参照を始めた時点とする。そこで確定しているイベントをすべて含め、seq_nr が指定値以上の封筒を昇順で返す（R-4〜R-6）。この同じ時点の読み取りは未合意である（MEM-D4）。

読み取りは強整合であり、結果整合の読み直しを必要としない。この整合性の前提も未合意である（MEM-D4・MEM-D5、SP-1）。2 つの公開操作を続けて呼んでも、両操作が同じ時点を読む保証はない。

MEM-D4 の代案では、開始時にヘッド h と h 以下の不変の記録を確保する。排他制御を解いた後も、指定値以上 h 以下を欠けずに返す。MEM-D5 の代案では各値を確定済みの状態から読むが、組は原子的でない。封筒の seq_nr がヘッドを上回る場合も R-8 の範囲内である。

## 6. 保持の失敗を追記の結果から分ける

- **草案・必須 MEM-10**: 保持件数がなければ現在のスナップショットだけを持つ。件数 n を設定した場合は、新しい n 件を残し、超過分を古い順に取り除く（S-1・S-2）。保持は追記の確定後、同じ排他制御の中で行う。イベントだけの追記でも、前回取り残した履歴を片付ける。この時機は未合意である（MEM-D6）。ジャーナルと集約ヘッドは保持処理で取り除かない。
- **草案・必須 MEM-11**: 保持の失敗は書き込みの成功を変えない。失敗は排他制御を解いた後にログで知らせる。次の追記後の保持処理で、現在の履歴を読み直して取り残しを片付ける（S-4）。ログと再試行の時機は未合意である（MEM-D7）。通知の失敗も、確定した追記の結果を変えない。

MEM-D6 の代案でも、追記の確定を保持の成否から分ける。排他制御を取り直した時点の履歴から、超過分を古い順に選ぶ。保持の失敗を理由に追記を取り消す案は S-4 に反するため、候補に含めない。

- **草案・任意 MEM-12**: 最初の版では S-3 の期限切れ方式を提供しなくてよい。草案は提供しない案であり、未合意である（MEM-D8）。代案で提供する場合は、猶予を設定の正の整数の秒数とする。印を付ける時点のストアの時刻に猶予を加え、秒単位の期限を保存する。occurred_at を期限の時計に使わない。印は 1 回だけ付け、印付きの履歴を件数に数えず、選び直さず、期限を延ばさない。各操作時に期限を確認して取り除くため、削除の遅れに上限はない。現在のスナップショットは期限切れにしない。

## 7. 変更フィードの提供と再同期を決める

- **草案・任意 MEM-13**: 最初の版では変更フィードを提供しなくてよい。草案は提供しない案であり、未合意である（MEM-D9）。代案で提供する場合は、すべての確定した追記のヘッド遷移を、ジャーナル・ヘッドと同じ確定に含める。未確定の遷移を配信しない（H-1・F-1）。利用者の通知処理を、確定の条件にしない。
- **草案・必須 MEM-14**（提供する場合）: 同じ集約の遷移を seq_nr の昇順で生成し、転送経路もその順序を保つ。重複はありうる。購読側は F-3・F-4 に従って重複を捨て、欠番をジャーナルから補う。遷移は保存先の寿命中、無期限に保持する。この保持と転送経路の性質は未合意である（MEM-D10）。
- **草案・必須 MEM-15**（提供する場合）: 購読位置を保存先の識別と結び付け、別の保存先の位置は再利用しない。初回購読や位置を失った場合は、排他制御の中で全集約の現在の seq_nr と、そこまでの遷移の境界を取得する。境界より後の遷移を保持したまま、購読側の位置と各集約を照合する。不足分をジャーナルから補い、その後、境界より後から購読する（F-5）。この再同期手順は未合意である（MEM-D9・MEM-D10）。

無期限保持でも、再同期の手順は省略しない。保存先の寿命が終わると、遷移だけでなくジャーナルも失う。新しい保存先から旧記録を補う保証はない。旧位置と混ぜず、新しい保存先として扱う。

MEM-D10 の代案では、保持期間を設定の正の整数の秒数とし、転送経路は順序を入れ替えうると明記する。最古の保持位置と購読位置を照合し、期限超過を検出したら MEM-15 の全件の再同期を行う。再同期中に必要な境界以後の遷移を保持できない場合は、その試行を終了し、新しい境界からやり直す。更新後に止まった集約も全件の照合対象に含める。

## 9. 適合確認で見る事例

草案の案を採用した場合に確認する事例である。未合意の判断の受け入れを先取りするものではない。

1. 独立して生成した保存先は混ざらず、明示的に共有した保存先は同じ記録と設定を見る。
2. 同じ集約へ同じ seq_nr を並行して追記すると、1 件だけが確定する。飛び番は契約違反になる。
3. スナップショットなしで新規作成できる。封筒のない集約もヘッドの seq_nr を返す。
4. 確定前に失敗を差し込むと、ヘッド・ジャーナル・スナップショットと、提供する場合のフィードのどれにも変更が現れない。
5. 読み取りと追記を重ねても、イベントの取得は開始時点まで欠けずに返る。原子的に読む案では、封筒の seq_nr は組のヘッドを上回らない。
6. 保持の失敗を差し込んでも、確定した追記は成功として返る。別経路で通知され、次の保持処理で古い履歴から片付く。
7. 保持件数 0 と未提供の能力の要求は設定エラーになる。別の集約の履歴は削除されない。
8. 書き込みの入力や取得結果を変更しても、保存済みの封筒とペイロードは変わらない。
9. フィードを提供する案では、再同期中にも追記し、境界以後の遷移が欠けないことを確かめる。有限保持の案では、更新後に止まった集約も再同期で補う。

## 10. 合意状況と次の判断

MEM-D1〜MEM-D12 はすべて未合意である。オーナーと一つずつ確認する。次の進め方は以下の 2 案である。

1. **推奨**: MEM-D1・MEM-D2・MEM-D12 の前提から順に合意し、確定・読み取り・保持・能力・設定へ進む。
2. 草案の候補の範囲を先に見直し、判断を追加・分割した後で、個別の合意に進む。
