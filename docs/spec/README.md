# event-store-adapter 仕様（v5）

各言語の event-store-adapter が従う仕様。ここに書かれた内容が正であり、どの言語の実装も参照実装ではない（[ADR-0001](../adr/0001-language-neutral-spec-based-on-envelope-model.md)）。用語は [CONTEXT.md](../../CONTEXT.md) に従う。

共通契約、DynamoDB とメモリのストレージプロファイル、キーに使うハッシュ（[storage/hash.md](storage/hash.md)）、適合テストデータ 1.0.0 は、v5 として確定している（P-47・P-49）。適合テストデータ 1.1.0 と 1.2.0 は、1.0.0 に v5 の規則のケースを足した版である（P-51・P-52）。v5 の文書は、本リポジトリのタグ `contract-v5` で固定して指せる（P-50）。SQLite と Bigtable のストレージプロファイルは 2026-10-16 に確定した（SQLite は P-53・P-54、Bigtable は P-55・P-56）。これは v5 の共通契約に対する確定で、タグ `contract-v5` の後に確定したので、タグの指す文書には含まれない。Spanner のストレージプロファイルだけが、具体的な実現方法が草案のままである。下の P-1〜P-56 は合意済みで（P-17〜P-40 は [PR #1](https://github.com/j5ik2o/event-store-adapter/pull/1) のレビューを受けて 2026-10-03 に、P-41 は適合テストデータを作る中で 2026-10-05 に、P-42〜P-45 は各言語の設計文書のレビューを受けて 2026-10-06 に、P-46〜P-48 は最初のメジャーの準備の中で 2026-10-13 に、P-49・P-50 は v5 の定義をはっきりさせる中で、P-51 は適合テストデータを 1.1.0 にする中で、2026-10-14 に足した。P-52 は適合テストデータを 1.2.0 にする中で、2026-10-15 に足した。P-53・P-54 は SQLite のプロファイルを確定する中で、P-55・P-56 は Bigtable のプロファイルを確定する中で、2026-10-16 に足した）、基になる ADR-0001〜0006 も `accepted` である。共通契約のほかの規則は、rs v3 の挙動を引き継いだもの（P-1 による）か、合意事項から導いたものである。新たに足した規則のうち R-7（P-14）・R-3（P-15）・S-3（P-16）も個別に合意済みである。仕様を変えるときは、リポジトリのオーナーの合意を得る。

共通契約の未決事項は残っていない。DynamoDB のストレージプロファイルは、これらの合意から導き、新たに必要になった判断 D-1〜D-9 も合意済みである（[storage/dynamodb.md](storage/dynamodb.md) の 1 章）。

## 構成

仕様は 3 層に分かれる。

| 層 | 文書 | 内容 |
|:--|:--|:--|
| 共通契約 | [core-contract.md](core-contract.md) | 保存先に依存しない意味論。型、4 つの操作、seq_nr の規約、エラー分類、スナップショット保持、変更フィード |
| ストレージプロファイル | [DynamoDB](storage/dynamodb.md)（D-1〜D-9 合意済み）、[Bigtable](storage/bigtable.md)（1 章の主要判断と草案の規則を確定。BT-15 は変更フィードを提供するときに確定）、[Spanner](storage/spanner.md)（SPN-D1a・SPN-D1b・SPN-D2〜D7 合意済み、具体的な実現方法は草案）、[SQLite](storage/sqlite.md)（1 章の主要判断と草案の規則を確定。SQ-13 は変更フィードを提供するときに確定）、[メモリ](storage/memory.md)（MEM-D1〜D9・MEM-D11・MEM-D12 合意済み、MEM-D10 は保留）。DynamoDB とメモリは v5 で確定（P-47）、SQLite も確定（P-53・P-54）、Bigtable も確定（P-55・P-56） | 保存先ごとの配置、確定、読み取り、保持、変更フィード |
| ストレージプロファイル共通 | [storage/hash.md](storage/hash.md)（v5 で確定、P-49） | キーにハッシュを使うプロファイル（Spanner・Bigtable など）が使う FNV-1a 64 とその入出力表 |
| 適合テストデータ | [conformance/](../../conformance/README.md)（v1.2.0、2026-10-15。v1.1.0 は 2026-10-14、v1.0.0 は 2026-10-05） | 言語に依存しない JSON で書いた入出力と期待結果。各実装は同じ内容を写して CI で版とハッシュを照合し、段階 2 で実行器を作って読み込む |

Spanner・Bigtable・SQLite の草案は 2026-10-04 に作成し、各プロファイルの 1 章にある主要判断をすべて合意した。SQLite と Bigtable は 2026-10-16 に、草案の規則も確定した（SQLite は P-53・P-54、Bigtable は P-55・P-56）。

Bigtable の判断は、外部での初期化、ジャーナル行への履歴配置、クラスタ固定、即時削除、最初の版では変更フィードを提供しないこと（BT-D8。提供するときは head の Change Streams、BT-D5）、封筒の固定バイナリ形式、ストア単位のサイズ上限、ヘッド更新前の必須の書き出しである。履歴配置は [ADR-0007](../adr/0007-store-bigtable-snapshot-history-with-events.md)、封筒の保存形式は [ADR-0008](../adr/0008-fix-bigtable-envelope-binary-format.md) に記録した。

Spanner は GoogleSQL、共通の接頭辞から生成する 5 テーブル、SERIALIZABLE の書き込みと強整合の復元、即時削除と TTL、任意の変更フィード、外部での初期化、保持件数のストア単位での統一、TTL の猶予を正の整数の日数で指定する API を採用した。

SQLite は同じホストのローカルファイル、WAL と synchronous=FULL、SQLite 3.51.3 以上、全テーブルの STRICT、BEGIN IMMEDIATE の追記と同じ時点の読み取り、確定後の履歴削除、最初の版では変更フィードを提供しないこと（SQ-D8。提供するときは同じ確定で書く遷移表を無期限に保持する、SQ-D5a・SQ-D5b）、明示的な初期化、保持・フィード設定のストア単位での統一を採用した。

主要判断の合意は、実装の適合を宣言するものではない。Spanner の草案と表示した規則の具体的な実現方法と、各言語の実装・保存先での検証は残っている。SQLite と Bigtable は規則を確定済み（Bigtable の BT-15 は変更フィードを提供するときに確定）で、各言語の実装での検証が残っている。共通契約の合意済み規則は変更していない。

メモリのプロファイルは 2026-10-05 に作成し、主要判断を合意した（[実装計画](../plan/implementation-plan.md)の IP-D4 による）。単一プロセスで永続化しない保存先とし、明示的な共有、ストア全体の排他制御による確定と同じ時点の読み取り（スナップショットとヘッドの組も原子的に読む）、確定後に同じ排他制御の中で行う保持、保持の失敗のログによる通知、保存先が持つ不変の設定、実装による並行呼び出しの保護を採用した。期限切れ方式と変更フィードは、最初の版では提供しない。フィードの保持と順序（MEM-D10）は、提供すると決めたときに決める。

### Spanner・Bigtable・SQLite の比較

| 項目 | Spanner | Bigtable | SQLite |
|:--|:--|:--|:--|
| 確定点 | 同じデータベースの SERIALIZABLE トランザクション | ヘッド 1 行の CheckAndMutateRow | 同じファイルの BEGIN IMMEDIATE / COMMIT |
| イベントの読み取り | 強整合の読み取り専用トランザクション | 取得済みヘッド h と、物理行 1〜h−1 の組 | 同じ読み取りトランザクション |
| ヘッドと最新スナップショット | 同じ読み取り時点 | 同じ行の原子的な読み取り | 同じ読み取り時点 |
| 履歴の保持 | 別トランザクションで削除または TTL の印付け | journal 行の履歴 payload を削除し、削除済みの印は残す | 確定後の別トランザクションで削除 |
| 期限切れ方式 | 提供。猶予は正の整数の日数で指定し DDL と照合（SPN-D3・D7 合意済み） | 最初の版では提供しない（BT-D4 合意済み） | 最初の版では提供しない（SQ-D4 合意済み） |
| 変更フィード | head の Change Stream を任意で提供。NEW_ROW（SPN-D4 合意済み） | 最初の版では提供しない（BT-D8 合意済み）。提供するときは head の Change Streams（BT-D5） | 最初の版では提供しない（SQ-D8 合意済み）。提供するときは同じ確定で書く遷移表（SQ-D5a） |
| 購読の保持期間 | 構成を照合。既定 7 日、最大 30 日 | 提供するときは構成を照合。1〜7 日 | 提供するときは無期限で、アダプタによる削除なし（SQ-D5b） |
| 主な制約・確認事項 | 方言、TTL の猶予、ストア単位の設定 | 書き出し失敗中の追記停止、保持の読み取り費用、封筒の上限 | 複数プロセス、WAL と同期、修正済み SQLite、遷移表の容量 |

保存先の性質の根拠、現行実装との違い、障害時の手順、実装時の受け入れ条件は各プロファイルに記録した。各言語の実装を変える前に、保存形式に焼き付く配置と設定を確認する。

## 規範の表記

各規則の先頭に、次のいずれかを付ける。

- **必須**: 適合する実装は必ず満たす
- **推奨**: 満たさない場合は理由を文書に書く
- **任意**: 実装してもしなくてもよい。実装するなら規則に従う

規則には `W-1` のような番号を振る。適合テストデータはこの番号を参照する。
